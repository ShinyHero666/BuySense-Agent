# 18 高级实验：只读搜推诊断 Agent

> **Legacy 教材**：本章是早期只读诊断实验，不代表墨圆智选当前产品入口；当前架构见 [Moyuan SAR Agent V2](../code/agent-control-plane/README.md)。

购买决策 Agent 是主线；搜推诊断 Agent 是高级实验。它不参与用户购买会话，不修改配置或发布模型，而是读取已有搜索/推荐 Trace，形成“证据 → 假设 → 单变量实验”的诊断建议。

## 1. 真实使用场景

运营反馈：“预算 700 元搜 iPhone 没有结果，是排序问题吗？”

错误做法是直接提高某个排序权重。诊断 Agent 先读取数量漏斗和 `filter_reasons`：如果召回有候选但价格过滤后归零，排序根本没有机会发挥作用。

```bash
PYTHONPATH=src:. python3 -m shoprec.cli diagnose-search iphone --max-price 700
```

输出包含严重级别、阶段、结构化证据、假设和下一实验。例如：保持 Query 不变，逐项移除非安全过滤器，比较候选量与硬约束违反数。

## 2. 只读工具边界

高级 Agent 只接受现有 Trace 或调用搜索读取。它不暴露：

- `record_event`、`save_shortlist`；
- 估价、订单、支付；
- 实验配置写入、发布、回滚；
- ModelPort 控制面或 Provider 密钥；
- 原始用户 PII。

诊断输出是建议，不是自动操作。即使建议看起来明显，也需要工程师评审和独立实验。

## 3. 规则基线

`diagnostic_agent.py` 识别：

- 风险 Query 在召回前被拦截；
- 非安全空结果和主导过滤理由；
- 某阶段候选 100% 损失；
- 单阶段高延迟；
- 单卖家或单型号导致的列表多样性偏低；
- 未发现明显异常时建立基准回放。

规则基线可离线评测、不会幻觉，也为之后的 ModelPort 总结实验提供标签。不要一开始就让模型自由读取全量日志。

## 4. 诊断流程

```text
选择一个 request_id
→ 读取脱敏 Trace/指标
→ 定位最早异常阶段
→ 引用数量、理由码、延迟证据
→ 生成不超过 3 个假设
→ 为每个假设设计单变量实验
→ 人工批准后由普通实验平台执行
```

购买 Agent 的 Trace 正好提供 ModelPort 路由、工具参数和证据；Part I 的 Pipeline Trace 提供召回到结果的阶段漏斗。两类 Trace 通过 request/run ID 关联，但权限域保持独立。

## 5. 优化实验

高级实验可以比较：

- 纯规则诊断 vs ModelPort 辅助摘要；
- 只给聚合漏斗 vs 给完整脱敏 Trace；
- 先定位阶段 vs 自由生成根因；
- 单变量实验模板 vs 开放建议。

主指标是根因阶段准确率、证据引用精确率和实验可执行率；护栏是错误写操作 0、隐私泄漏 0。延迟不是第一优先级。

## 6. 生产化边界

生产实现应把诊断 Agent 放在只读副本或观测平台之后，使用短期凭证和最小字段视图。所有建议保留 request ID、数据窗口、版本和审批人。自动改权重、自动放量或自动回滚属于另一个高风险系统，不在本实验范围内。
