# 00 课程地图与学习方法

> **Legacy 教材**：本章属于早期搜索推荐课程与二手案例，不代表墨圆智选当前产品主线；当前架构见 [Moyuan SAR Agent V2](../code/agent-control-plane/README.md)。

## 1. 课程要解决什么问题

这套课程训练的不是某个搜索框架或推荐 SDK，而是构建在线搜推系统时可迁移的工程能力：

1. 把业务目标翻译成阶段、接口、数据和指标。
2. 用候选漏斗组织 Query、召回、过滤、排序和重排。
3. 用 Trace、理由码和实验版本解释每个结果。
4. 建立曝光、点击、收藏、购买到特征和模型的数据闭环。
5. 让服务具备校验、超时、降级、灰度、回滚和扩缩容能力。

贯穿案例使用墨圆自有教学品牌与合成二手商品。搜索请求以 Query 和筛选条件为入口；推荐请求以用户、场景和上下文为入口；两条链路共享商品、候选、特征、实验和可观测性。实现细节均为教学设计，不声称对应真实生产架构。

## 3. 先运行，再阅读

进入代码目录并完成初始化：

```bash
cd moyuan-sar-agent/code
bash scripts/bootstrap.sh
```

本课程以 Linux 文件系统和 Bash 为执行基准：路径分隔符使用 `/`，可执行文件位于 `.venv/bin/`，HTTP 调试使用 `curl`。脚本会自行定位代码根目录，因此从任意目录调用绝对脚本路径也能工作。

先运行一段带讲解的搜索导览：

```bash
bash scripts/quick-search.sh --section rewrite
```

再分别观察摘要、Trace 和逐商品解释：

```bash
.venv/bin/shoprec search "苹果手机" --view summary
.venv/bin/shoprec search "手机" --view trace
.venv/bin/shoprec search "手机" --view explain
.venv/bin/shoprec recommend --user u001 --view trace
.venv/bin/shoprec compare-flowpool --size 8
```

## 4. 三遍学习法

### 第一遍：只画链路

先忽略公式和类名，只记录：

```text
输入 -> 阶段 -> 阶段 -> 输出
```

在每个箭头上写候选数量，例如：

```text
搜索：18 -> 12 -> 8 -> 8 -> 5
推荐：30 -> 21 -> 14 -> 10 -> 8
```

候选数量突然下降，通常意味着召回条件、硬过滤或配额有问题；数量突然膨胀，通常意味着去重、截断或配置失效。

### 第二遍：跟踪一条请求

搜索使用“苹果手机，价格不超过 7000 元”，推荐使用用户 `u001`。逐阶段回答：

1. 请求如何归一化和改写？
2. 商品由哪些召回器命中？
3. 哪些商品被过滤，理由码是什么？
4. 每个排序层使用了哪些特征？
5. 实验版本如何改变权重或配额？
6. 重排为什么改变商品位置？
7. 结果何时写入曝光存储？

### 第三遍：主动制造故障

完成正常链路后再练习异常：

- 把某类商品库存全部设为 0。
- 使用不存在的城市筛选。
- 将兴趣池配额提高到 100%。
- 注入模型重排超时。
- 将曝光 TTL 设置得过长。
- 提交非法实验流量或权重配置。

要求只使用结构化错误、Trace、数量漏斗和理由码完成解释。

## 5. 每个阶段都问六个问题

无论学习搜索还是推荐，都用同一组问题审查阶段：

1. 输入和输出类型是什么？
2. 候选数量应增加、减少还是保持？
3. 依赖哪些在线数据和配置？
4. 超时、异常或数据缺失时如何降级？
5. 哪些指标证明阶段工作正常？
6. 如何通过实验验证改动带来的因果效果？

如果这六个问题答不完整，说明对阶段的理解仍停留在“知道名字”。

## 6. 课程约定

- **教学实现**：为本机可运行而缩小数据规模和基础设施复杂度。
- **参考公式**：展示变量关系，不代表可直接上线的模型参数。
- **生产建议**：面向高并发、数据一致性、成本和治理的演进方向。
- **阶段契约**：代码和测试共同保证的输入、输出与顺序。
- **理由码**：可聚合、可监控的结构化决策原因。
- **降级**：依赖失败时保留最低可用结果，同时暴露异常状态。

课程不要求特定云、语言或中间件。Elasticsearch、Redis、Kafka、Flink 和 Kubernetes 是生产替换示例，核心学习对象是它们承担的逻辑职责。

## 7. 验收标准

完成课程后，应能独立做到：

- 为新搜索场景设计 Query、召回、过滤、排序和重排链路。
- 为新推荐场景设计十阶段 Pipeline 和 Flow Pool 配额。
- 解释多路召回的重叠、去重、补量和归因。
- 设计粗排、精排和重排的候选规模与延迟预算。
- 避免训练与推理特征不一致。
- 设计稳定分桶、互斥实验层和配置回滚。
- 从空结果、延迟升高或指标下降定位到具体阶段。
- 把内存实现替换为搜索引擎、特征库、事件流和模型服务。
- 写出包含容量、降级、观测、灰度和回滚的生产技术方案。
- 跑通搜索、比较、明确确认和清单保存的购买决策 Agent。
- 用 ModelPort 路由证据和离线门禁定位并优化模型/工具问题。
- 保持诊断 Agent 只读，不让建议直接变成线上配置写入。
